# ADR-007: Public Display Privacy

**Status:** Accepted (amended 2026-10-25)
`/display` is unauthenticated and serves only a dedicated projection (JSON/Inertia partial reloads) with exactly: masked patient identifier (first **3** characters replaced with `*`, safe for short IDs), name initials, bed number, sex label, age (**band by default; exact age only behind an approved branding toggle**), duration = elapsed minutes since current allocation start (client-side ticking, no full refetch), treatment status label. Never: full names/IDs, ULIDs, contacts, notes, diagnoses, historical records. Only currently allocated patients. Expose an administrative enable/disable toggle for the display.

**Amendment 2026-10-25 (product decision):** the hospital-wide `/display` waiting-room concept is **retired**. The display scope is now **per ward**: an unauthenticated full-screen page `/display/{ward}`, surfaced when a ward is created, showing a table of that ward's **occupied beds** with the columns: masked patient ID, patient initials, bed number, sex, age, duration, patient treatment status, **managing team label**, and bed occupancy status. Two implications: (1) the displayed team label must be a hospital-approved role/team name, never ULIDs or personal data; (2) all displayed values continue to come exclusively from the allocation (CIMA-060) and treatment-status (CIMA-052) workflows — the public page is read-only projection, never an entry point. All original privacy prohibitions remain unchanged; the aged band-vs-exact toggle decision (R3) still applies.
